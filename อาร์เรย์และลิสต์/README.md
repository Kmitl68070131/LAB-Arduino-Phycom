## โครงสร้างข้อมูลและตัวแปร

อ่าน `SensorHistory.h` ในแต่ละ sketch เป็นโค้ดชุดเดียวกัน ไม่ต้องติดตั้งไลบรารี List เพิ่ม

| ส่วน | ความหมาย / ตัวอย่าง |
|---|---|
| `float values[20]` | array เก็บค่าจริงเช่น 25.1,25.3,25.2 |
| `nextWrite` | ช่อง array ที่จะเขียนรอบหน้า วนกลับเมื่อครบ 20 |
| `count` | จำนวนข้อมูลที่มีจริง 0..20 ไม่อ่านช่องที่ยังไม่ได้เก็บ |
| `Node` | โหนดของ singly linked list มี `value` และ `next` |
| `pool[20]` | array ของโหนดที่จองไว้ล่วงหน้า ใช้หน่วยความจำคงที่ |
| `head / tail` | pointer โหนดเก่าสุด / ใหม่สุด |
| `node->next` | pointer เดินไปโหนดถัดไป ไม่ใช่ index array |
| `append(value)` | เพิ่มค่าเดียวลงทั้ง array และ list; เต็มแล้วแทนเก่าสุด; ปฏิเสธ NaN/Inf |
| `arrayAt(index)` | อ่านลำดับจากเก่าสุดแบบ O(1) ด้วยการคำนวณตำแหน่งวงแหวน |
| `listAt(index)` | อ่านจาก head แล้วเดิน next จนถึง index แบบ O(N) |
| `clear()` | ล้างจำนวน/หัว/ท้าย เริ่มใช้พื้นที่เดิมใหม่ ไม่ขอ heap |
| `primaryHistory / humidityHistory` | ประวัติค่าหลัก / ความชื้น DHT แยกคนละหน่วย |
| `selectedIndex / showList` | ลำดับที่เว็บเลือก / false=array, true=list |
| `historyRequested` | flag ให้ loop ส่งประวัติ หลีกเลี่ยง publish ภายใน callback |

### ตัวอย่างการประยุกต์

- อุณหภูมิ/แสง/ระยะ: ดูย้อนหลังว่าค่าเปลี่ยนอย่างไร และเลือกค่าที่ต้องการกลับมาแสดง LCD
- ปุ่ม/PIR: เก็บลำดับสถานะ 0/1; Keypad: เก็บปุ่มใหม่เป็น ASCII เช่น '1'=49, 'A'=65
- DHT: มีสองช่อง ประวัติอุณหภูมิไม่ปนกับความชื้น
- ปุ่ม ButtonEvents: `press_count` นับขอบกด แต่ประวัติเป็นค่าของทุก telemetry รวม snapshot และขอบปล่อย จึงห้ามใช้ความยาว list เป็นจำนวนกด

ลิสต์ในชุดนี้เป็น **ลิสต์เชื่อมโยงจริงที่ใช้ pointer** แต่โหนดอยู่ใน pool คงที่ ไม่มี new/delete ขณะทำงาน เหมาะกับ RAM ของไมโครคอนโทรลเลอร์ เก็บชุดเดียวซ้ำสองโครงสร้างเพื่อเรียนรู้การเข้าถึงข้อมูล ในงานจริงเลือกใช้โครงสร้างเดียวเพื่อลด RAM

เมื่อเต็ม เช่นรับ 1..25 จะเหลือ **6..25** ทั้งสองโครงสร้าง; index 0 คือ 6, index 19 คือ 25 เมื่อมีค่าใหม่ index อ้างตำแหน่งในหน้าต่างปัจจุบัน ไม่ใช่ ID ถาวร
ส่งออก array เดิน N ค่า และส่งออก linked list เดิน next ครั้งเดียว O(N); เรียก listAt ทีละ index จะช้ากว่า จึงใช้เฉพาะเลือกดูรายการบน LCD

## เริ่มใช้งาน

1. เลือกตัวอย่างจากตาราง แล้วต่อสายตาม README ของอุปกรณ์นั้น
2. LCD ทุกชุด: VCC→5V, GND→GND, SDA→SDA/A4, SCL→SCL/A5; address 0x27 แก้เป็น address จริงและปรับ contrast
3. ลง Arduino UNO R4 Boards, MQTT by Joel Gaehwiler, ArduinoJson **7**, LiquidCrystal I2C; Keypad/DHT ลงเพิ่มตาม [ตารางไลบรารี](../MQTT/LIBRARIES.md#ไลบรารีที่ต้องติดตั้ง)
4. เปิด .ino ของชุดนั้นพร้อม .h ในโฟลเดอร์เดียวกัน แก้ Wi-Fi/Broker → Upload → เปิด Serial 115200
5. ที่ root repo:

```sh
cd MQTT/web
npm ci
npm start
```

6. เปิด http://127.0.0.1:3000 → เลือกโหมด **อาร์เรย์และลิสต์ — เก็บประวัติเซนเซอร์** และอุปกรณ์ให้ตรง
7. เปลี่ยนค่าเซนเซอร์ รอเก็บข้อมูล ดูตารางค่าใน array/list ซึ่งควรตรงกันทุกแถว
8. เลือกโครงสร้างและ index แล้วกด **ดูรายการบน LCD** → ACK → WEB RX 5 วินาที → LCD แสดง ARRAY/LIST, index, N และค่าที่เลือกเมื่อรอบอ่านถัดไป
9. **ขอประวัติ** ส่งข้อมูลที่เก็บแล้วทันทีเมื่อ MQTT พร้อม; **ล้างประวัติ** ได้รายการว่างก่อนรอบอ่านใหม่

บอร์ดและ Node ต้องเข้า broker เดียวกันได้; ค่าเริ่ม phycom.it.kmitl.ac.th:1883 อาจจำกัดเครือข่ายห้องเรียน GitHub Pages ไม่รัน Node bridge ต้องเปิดจาก localhost หรือจัด backend เอง

## คำสั่งจากเว็บ

Topic: `68070131/collections/<ชื่ออุปกรณ์>/command` ใช้ชื่อรหัสเดิมเช่น TMP36, ButtonEvents (เว็บแสดงชื่อไทย)

| คำสั่ง JSON | ทำอะไร |
|---|---|
| `{"request_history":true}` | ส่งประวัติที่เก็บไว้ทาง `/history` ไม่อ่านค่าเพิ่ม |
| `{"structure":"array","history_index":0}` | LCD ดู array ลำดับเก่าสุด |
| `{"structure":"list","history_index":2,"request_history":true}` | LCD ดูโหนดลำดับ 2 และส่งประวัติกลับเว็บ |
| `{"clear_history":true,"request_history":true}` | ล้างทั้งสองโครงสร้างทุกช่องแล้วส่ง snapshot |
| `{"text":"Hello LCD"}` | รับข้อความเว็บมาแสดง Serial และ LCD |
| `{"interval_ms":5000}` | ปรับช่วงอ่าน/ส่งค่าเป็น 5 วินาที (ButtonEvents เป็นช่วง snapshot) |

`history_index` integer 0..19; `structure` ต้อง string array/list; `request_history` และ `clear_history` ต้อง boolean; interval_ms integer 2500..60000; ผิดชนิดส่ง ACK error ก่อนเปลี่ยนค่าตั้ง
เลือก index ที่ยังไม่มีข้อมูลได้ แต่ LCD แสดง **INDEX NOT READY** ไม่อ่านหน่วยความจำเกินขอบ `reset` เดิมล้างสถิติเท่านั้น หากล้างประวัติให้ใช้ clear_history; ทั้งสองคำสั่งไม่ล้าง press_count ของ ButtonEvents

ข้อความส่งกลับ `/ack` มี result และ text; `/history` มี primary และ (DHT) humidity พร้อม count/array/list; publish ACK/history ทำใน loop ไม่ทำใน callback

## ข้อมูลที่ส่งขึ้นเว็บ

Topic `68070131/collections/TMP36/telemetry` เช่น:

```json
{
  "sensor":"TMP36","channel":"TMP36","unit":"C",
  "value":25.3,"valid":true,"uptime_ms":10000,
  "structure":"array","selected_index":0,
  "history":{"count":3,"array":[25.1,25.2,25.3],"list":[25.1,25.2,25.3]}
}
```

`history.array/list` เป็น JSON arrays ทั้งคู่เพราะ JSON ไม่มีชนิด linked list ต่างกันที่โครงสร้างใน RAM ของบอร์ด ค่าที่ส่งเรียงเก่าไปใหม่
เมื่อ valid=false/value=null ประวัติเดิมยังส่งแต่ไม่เพิ่มค่า; DHT มี telemetry 2 ข้อความแยก channel; Serial พิมพ์ JSON เต็ม ส่วน LCD 16×2 แสดงค่า index ที่เลือกและหน่วย ไม่สามารถแสดง 20 ค่าพร้อมกัน

## ทดสอบและข้อจำกัด

จาก root repository:

```sh
g++ -std=c++11 อาร์เรย์และลิสต์/tests/history.cpp -o /tmp/history-test
/tmp/history-test
cd MQTT/web
npm test
```

ทดสอบโครงสร้างจริง 1,000 ค่า เทียบกับ reference queue รวมหน้าต่างเต็ม วน ring ล้างแล้วเติมใหม่ NaN/Inf index ผิด และแยกความชื้น จากนั้นทดสอบ HTTP bridge รองรับโหมด collections

- เป็นข้อมูลใน RAM ปิดไฟแล้วหาย ไม่ได้บันทึกฐานข้อมูล/SD
- เก็บได้ 20 ค่า/ช่อง; offline ยังเก็บเมื่อ loop อ่านทัน ขอ history ที่ยังอยู่ได้เมื่อเน็ตกลับมา แต่ telemetry เก่าที่หลุดไม่ถูกเข้าคิวส่งย้อนหลัง
- เน็ต reconnect อาจบล็อกการอ่านชั่วคราว; ไม่ใช้แทน data logger แบบเวลาคงที่หรือ pulse counter ความเร็วสูง
- ใช้ MQTT buffer 2048 bytes; อย่าเพิ่มความจุโดยไม่วัด payload/RAM และปรับ buffer ให้เพียงพอ
- ข้อความ LCD ใช้ ASCII ตาม ROM ทั่วไป
- ยังไม่ได้ compile ด้วย Arduino toolchain หรือทดสอบบอร์ด/LCD/broker จริงในสภาพแวดล้อมนี้
